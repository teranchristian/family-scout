# Event discovery and weather — one shared workflow

Use this reference for **any broad dated or undated activity search**. Local and nearby event agents receive the **same instructions**, differing only in their assigned area. Do not create separate local-vs-nearby rules.

## Shared instructions for Agent 1 and Agent 2

Inputs: public area/suburbs; absolute dates (or the stated undated horizon); children's **derived age bands**, any explicit attending subset, budget/radius/preferences and requested language. Never receive the private family profile, birthdates, names or home coordinates.

1. Search **fresh, current sources** in your assigned area: council **general event calendars**, library/event-program calendars, community centres, neighbourhood groups, parks, galleries, seasonal events, workshops, festivals, performances and hands-on experiences. Don't search only for pages labelled "kids"; interesting general events can fit families too.
2. Look for **free council/community events first**, but include unusually worthwhile paid options. Prioritise one-off, seasonal, educational, interactive or surprising experiences over ordinary playgrounds and generic attractions. Include worthwhile everyday options when the date has few special events.
3. **Check every requested day separately**. A calendar listing or search snippet is a lead, not proof that the event runs on the requested date. Read the current organiser/official event page when possible. Verify exact date/time, the offered activity, age restrictions, admission/group cost, booking requirement and venue. Check cancellations and special closures; ordinary opening hours do not prove a scheduled program is on.
4. Judge **participation for each attending child's age**, not only that a venue admits children. Note when one child can mainly watch while another participates. Keep a good venue if one promoted feature is closed **but another worthwhile activity is actually available**.
5. Return compact, deduplicable leads: `title, date/time, suburb, venue/address if evidenced, short description, child-age fit and limits, price, booking, official URL, verification status, caveat`. Include exact source URLs, not opaque search handles. Identify unverified facts explicitly. Don't invent candidates to meet a count.

Across both discovery agents, **aim for 10–15 distinct useful leads when they exist**, then let the parent rank the best. This is a goal, not a hard minimum. Stop low-yield searching rather than endlessly retrying broken pages. Prefer batching page reads when the working reader supports it; one blocked/404 page should not trigger repeated identical retries. If a page is inaccessible, use an accountable alternative or mark the fact unverified.

## Agent 3: weather only

Check the forecast for **each requested date at the activity location** using available current weather data. Give high/low temperatures when supported, chance/amount of rain, wind or heat risks where relevant, and a concise outdoor/indoor implication. Note forecast uncertainty and dates outside forecast range. Do **not** research events or treat forecast as permission to ignore outdoor candidates unless the user asked for indoor-only.

## Parent: verify, rank and present

Merge the two event lists; deduplicate by event, venue and session date. Local discoveries get a fair chance: favour a strong nearby event over a similarly good famous attraction. Rank by actual enjoyment and age fit, specialness, distance/convenience, cost, toddler practicality and forecast. User hard constraints override preferences.

Before recommending an item as confirmed, **open its direct official/organiser page** and check date/session, suitability, price when claiming "free", mandatory booking and relevant cancellations. A source page is proof only for what it says. Unknowns remain labelled **Needs checking**, especially for hard constraints. If a booking is required, distinguish "booking required" from a confirmed available slot. Do not claim live availability without evidence.

Use an exact public venue address, when evidenced, to form a Google Maps search link; never invent coordinates or driving time. Do not present a generic council homepage as the direct event link if the event page exists. If the URL is broken, redirected to unrelated content or only a snippet, omit it or label it unverified. Check each factual link before displaying it.

Answer directly: short daily weather, a readable ranked top five if available, up to 3–5 extra discoveries, a useful pick for each requested day and one indoor backup when appropriate. Include an explicit **Good for: both / [one child] / the other child** line with a brief reason. Mention the family price or "price not confirmed", time, place, official URL and map. Never pretend a recommendation is a booking. No mandatory saving, renderer, research audit or hard-coded quotas.
